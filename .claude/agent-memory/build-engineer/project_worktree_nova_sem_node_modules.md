`node_modules/` é ignorado pelo git, logo **cada worktree precisa do seu
`npm ci`**. Sem isso o `run.sh` completo dá vermelho enganoso:

- `suites`/`suites-heavy`: 22 + 1 problemas, todos na forma
  `[FAIL] <suite>: sem contagem na última linha: (sem saída)` — é
  `MODULE_NOT_FOUND` de jsdom, não produto;
- `regra-morta`: 5 alíneas como `instrumento ausente: .claude/verify/regra_morta.js
  — NÃO EXECUTADO`, embora o arquivo **exista em HEAD e no disco** (quem falha é o
  processo filho que o lê);
- **`env-doctor` PASSA** nesse estado: ele valida node/python/git/Chromium, não
  dependências instaladas. Não é SKIP silencioso, é cobertura que não existe.

Medido em 2026-10-10 na worktree `phase5-r11`: antes do `npm ci`, 15 PASS · 3
FAIL; depois, **18 PASS · 0 FAIL**, sem tocar uma linha de código.

Armadilha adjacente: `grep -c $'\r' <arquivo>` pela ferramenta Bash **acusou CRLF
em arquivo 100% LF** (contou todas as linhas). Medir fim de linha só com bytes:
`python -c` contando `b"\r\n"`, ou `git hash-object` contra o blob.

**Why:** gastei um ciclo atribuindo a produto um vermelho que era ambiente — é
exatamente a R2 §3 (isolar ambiente/plataforma/path ANTES de concluir).

**How to apply:** worktree nova ou pipeline vermelho com "(sem saída)" → primeiro
`ls node_modules` e `npm ci --no-audit`; só depois diagnosticar. Nunca usar
`grep $'\r'` como prova de fim de linha. Ver [[rito-de-medicao]].
